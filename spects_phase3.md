# 5. ATTENDANCE SYSTEM

## 5.1 Login Tracking

When a valid employee logs in:

- The server must record the login timestamp.
- The timestamp must be generated by the server.
- The client must NOT be able to provide or override loginAt.

The employee must not be able to manually change the actual login timestamp.

Use the existing authentication flow.

Do not create a second authentication mechanism.

---

# 5.2 Logout Tracking

When an authenticated employee logs out:

- The server must record logoutAt.
- logoutAt must be generated by the server.
- The client must NOT be able to provide or override logoutAt.

The employee must not be able to manually modify the actual logout timestamp.

---

# 5.3 Working Duration

When both loginAt and logoutAt exist:

Calculate:

totalMins = difference between logoutAt and loginAt in minutes.

Example:

Login:
09:30

Logout:
17:50

Working duration:
500 minutes
= 8 hours 20 minutes

Do not trust a client-provided totalMins value.

Calculate it on the server.

---

# 5.4 Multiple Login Attempts

The implementation must safely handle repeated login attempts.

Do not create multiple active attendance records for the same employee/work date unless the existing product design explicitly requires multiple sessions.

Prefer one attendance record per employee per work date.

Use an appropriate database uniqueness constraint if compatible with the existing schema.

If the employee already has an attendance record for the current work date:

- Reuse/update the appropriate attendance record.
- Do not create duplicate attendance rows accidentally.

---

# 12. CALL CREATION VALIDATION

- leadId must be a valid existing Lead.
- calledAt must be a valid date/time.
- durationSec must be a non-negative integer.
- outcome must be a valid call outcome.
- remarks must respect reasonable length limits.
- nextFollowUp must be a valid date/time or null.

Do not allow the client to provide:

- userId

Do not allow a client to impersonate another counsellor.

# 13. LEAD RELATIONSHIP

Every CallLog must reference a valid Lead.

Before creating a call:

1. Authenticate the user.
2. Find the lead.
3. Verify the lead exists.
4. If COUNSELLOR, verify:

assignedToId === req.user.id

5. Only then create the CallLog.

Return:

404

if the lead does not exist.

Return:

403

if the counsellor does not own the lead.
